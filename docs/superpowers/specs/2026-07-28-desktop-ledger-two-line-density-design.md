# PC 端标的台账双轨密度设计

## 目标

在不删除、折叠或弱化现有字段的前提下，把“总览 → 标的台账”的桌面端每条记录稳定压缩为两条信息轨道，目标数据行高度约为 50–58px。移动端继续沿用分组卡片布局。

## 方案选择

采用固定双轨布局，而不是单纯缩小字号或隐藏次要内容。每个表格单元格都包含主、辅两行，所有令牌保持可见且禁止随机换行。桌面可用宽度不足时，表格容器提供横向滚动，避免用第三行换取适配。

## 信息编排

| 列 | 第一行 | 第二行 |
| --- | --- | --- |
| 标的 | 中文名或代码 | 代码、交易所、资产类型 |
| 结论与表现 | 最新有效评级、评估日期 | 方向、验证周期、收益、Alpha、方向结果、目标价结果 |
| 可靠性与变化 | 验证周期、样本可靠性、排除统计 | 上次评级到本次评级的演化 |
| 运行 | 最新任务状态或异常入口 | 成功、运行、排队、异常及总任务数 |

缺少某类数据时仍保留对应轨道并展示现有的空状态或权限提示，以维持扫描节奏。

## 响应式行为

- `821px` 以上启用紧凑桌面表格、两条信息轨道和表格最小宽度。
- 桌面窗口小于表格最小宽度时只在台账容器内横向滚动。
- `820px` 以下维持当前卡片化表格；取消桌面端的强制单行规则，让内容自然换行。

## 可访问性与交互

- 保持语义化 `table`、列标题、详情链接和现有可访问名称。
- 不通过 CSS 截断、隐藏或悬停内容承载唯一信息。
- 状态色、方向正确/错误的色彩语义及键盘访问保持不变。

## 验证

- 组件测试验证每个桌面单元格具备两条结构化信息轨道，并确认所有现有业务字段仍在 DOM 中。
- 执行完整前端测试、类型检查、Lint 与生产构建。
- 检查生产 bundle 已更新；Caddy 继续直接服务 `web/dist`，不重启 API、Gateway 或 Worker。

## 范围

仅修改外部 Web 管理端的台账组件、样式和测试，不修改 API、数据库或 `TradingAgents/`。
