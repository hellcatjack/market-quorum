# 报告准确性优化计划设计

## 目标

在不修改 `TradingAgents/` 子项目、不覆盖既有报告和验证结果的前提下，把 Market Quorum 从“能够生成和回放研究报告”升级为“能够识别数据污染、声明可验证预测、与基线公平比较、验证历史辅助价值并模拟组合影响”的研究审计平台。

本计划不把历史样本中的方向正确率直接解释为可交易收益，也不以模型生成的叙述代替结构化预测。所有新能力均位于外部平台层，并通过版本化合同与既有 `Decision`、`validation.v1`、`validation.v2` 并存。

## 已确认的现状

- 既有 `validation.v2` 的期限合同固定为 1、5、20 个交易日。
- `validations` 以 `(run_id, horizon)` 唯一，直接改变旧记录语义会破坏不可变审计。
- 历史记忆当前会选择已完成验证，但没有按点时数据完整性过滤来源评估。
- Alpha Vantage 财务报表记录的 `fiscalDateEnding` 是会计期间结束日，不是信息公开日；仅按该字段过滤不能防止历史评估读取未来发布的数据。
- 既有验证从大于等于分析日的第一个交易会话收盘开始，不能表达“报告完成后下一可交易时点成交”的执行语义。
- 既有最终判断通常缺少结构化目标价、置信度、仓位和明确的预测期限，因此不能可靠进行目标命中率、校准度或组合收益分析。

## 方案选择

### 方案一：原位扩展现有 Decision 和 Validation

优点是代码路径短。缺点是同一字段会承载多种预测和评分语义，旧客户端难以区分结果，20 日验证还会与既有唯一约束冲突。该方案不采用。

### 方案二：平台内版本化预测契约与完整性审计

原始 TradingAgents 决策、证据和旧验证保持不变；平台新增独立的完整性判断、预测合同、验证版本、实验和组合模拟。REST、MCP 与 Web 通过追加资源读取新能力。该方案兼顾审计、迁移成本与当前部署规模，为推荐方案。

### 方案三：独立分析数据仓库或服务

隔离最彻底，但会引入第二套身份、权限、任务调度、数据同步和运维边界。当前样本量和使用范围不足以抵消复杂度，暂不采用；平台内模型达到容量瓶颈后再拆分。

## 总体架构

```text
TradingAgents 原始评估（只读、不可变）
                │
                ├── PointInTimeAuditor ── 数据可用性与污染状态
                │            │
                │            └── safe / at_risk / unknown
                │
                ├── ForecastCompiler ──── forecast.v1（外部衍生、可追溯）
                │            │
                │            └── 20 / 60 / 120 交易日预测
                │
                ├── ValidationEngineV3 ── 下一可交易时点、成本前结果、基线
                │
                ├── MemoryExperiment ──── 独立 / 历史辅助成对实验
                │
                └── PortfolioReplay ───── 仓位、成本、回撤、基准
                             │
                             ▼
                REST / MCP / Web / 审计产物
```

所有派生结果保存输入哈希、策略版本、模型路由和生成时间。任何派生失败不得把原评估从 `succeeded` 改为失败。

## 子项目一：点时完整性与污染隔离

第一阶段建立统一 `PointInTimePolicy` 和财务报表可用日解析器。

- 美国证券优先使用 SEC 申报元数据，将报表期间映射到真实申报日期。
- Alpha Vantage `reportedDate` 仅可在映射唯一且规则验证通过时作为次级可用日。
- 无可验证公开日期的历史财务记录不传给 TradingAgents，采用 fail-closed。
- 当前快照、社交数据、宏观数据和新闻继续分别使用现有禁用、FRED vintage 和日期窗口策略。
- 每次评估产生策略版本化的完整性结果及永久审计产物。

既有评估离线重审后分为 `safe`、`at_risk`、`unknown`。默认准确率、历史记忆和实验只使用 `safe`；管理员仍可查看所有记录和排除原因。风险记录不删除、不回写原报告，干净重评估通过关联 run 表达。

详细边界见 `2026-07-27-point-in-time-integrity-design.md`。

## 子项目二：结构化预测与可信验证

### forecast.v1

平台在原报告成功封存后运行外部预测编译器。编译器只读取已封存决策、报告、证据索引和运行配置，不调用新的市场数据。输出保存为独立、不可变的结构化记录，并明确标注为平台衍生预测，而非 TradingAgents 原始输出。

核心字段包括：

- `as_of`、基准标的、预测口径（绝对收益或相对基准）。
- 20、60、120 个交易日的方向、预期收益区间和可选目标价。
- 置信度及其含义版本。
- `Hold` 的 `neutral_reason`：`expected_range` 或 `evidence_insufficient`。
- 可选目标仓位、最大仓位、失效条件和风险边界。
- 原报告哈希、编译模型、思考深度、提示词版本和编译状态。

编译器使用严格 JSON Schema。无法从报告形成可信预测时写入 `unavailable` 或空字段，不猜测数值。编译失败不影响原 run 成功状态，并可独立重试而不覆盖已完成版本。

### validation.v3

- 默认期限为 20、60、120 个交易日；旧 1/5/20 日验证继续保留。
- 入场定义为分析日之后第一个可交易会话的可执行价格；具体采用次日开盘并应用拆股标准化。
- 退出使用对应期限会话的收盘，保存未扣成本和按策略扣成本的结果。
- 每个预测明确选择绝对收益或相对基准口径，评分不再依赖评级名称隐式切换。
- `evidence_insufficient` 视为弃权，不计入方向正确率分母，单独显示覆盖率和弃权后表现。
- `expected_range` 按冻结的中性区间评分，不再统一使用固定正负 3%。
- 继续保存价格收益、总回报、Alpha、MAE/MFE、公司行动、供应商和封存行情。

### 基线与统计

同一入场、退出、价格数据和成本口径下计算：

- 始终看多、始终看空、始终中性。
- 20 日价格动量。
- SPY 买入持有及相对基准结果。
- 后续存在可靠行业映射时再增加行业中性基线，不在首版伪造映射。

聚合结果必须显示样本量、符合条件数量、排除数量、覆盖率和区间估计。普通比例提供 Wilson 区间；跨多次同标的评估的总体比较增加按标的分组的 bootstrap 区间，避免把高度相关样本当作完全独立。

## 子项目三：历史辅助实验与组合验证

### 历史辅助 A/B

实验服务为相同标的、分析日期、分析师、深度、语言、模型和思考深度创建配对变体：

- A：`memory_mode=independent`。
- B：`memory_mode=historical`。

同一对变体随机执行顺序，但针对同一标的串行，避免并发数据和资源竞争。实验冻结模型路由与配置快照。只有分析日前已经成熟且完整性为 `safe` 的来源可进入 B 组记忆；新完整性策略不得回写旧 memory snapshot。

结果按配对差异、覆盖率、方向正确性、相对收益、回撤和置信度校准比较。单对评估只作为案例，不声明统计优势；累计样本使用配对 bootstrap 或相应非参数检验。

### 组合级回放

组合回放是评估工具，不连接交易执行。输入包括初始资金、已有持仓、仓位上限、现金约束、手续费和滑点。执行统一采用下一可交易时点，输出：

- 毛收益与净收益。
- 相对 SPY 收益。
- 最大回撤、波动、换手率和成本。
- 单标的贡献、仓位冲突和未执行原因。

没有结构化仓位或执行规则的预测不能自动进入组合回放，页面必须显示“不可模拟”而不是补造仓位。

## 数据与 API 兼容原则

- 原 `Decision`、`Validation`、Evidence 和 Artifact 记录均不重写。
- 新资源采用独立版本字段和追加式迁移；旧 REST/MCP 响应字段不删除。
- 旧客户端继续读取 `validation.v1/v2`；新客户端显式请求完整性、forecast 和 v3 outcome。
- 所有列表和准确率接口默认排除非 `safe` 结果，同时返回排除计数；管理员可显式查看全量。
- 所有自动重试使用幂等键，成功派生结果不可原位覆盖。
- 数据源适配器以能力合同接入，未来 Alpha Vantage Premium、SEC 或其他供应商不会改变上层评分语义。

## Web 展示

评估详情增加：

- 点时完整性状态和排除原因。
- 原始判断与平台衍生预测的清晰分区。
- 20/60/120 日预测及逐期验证。
- 弃权、基线、数据质量和执行假设。

研究台账增加：

- 符合条件准确率与排除数。
- 相对基线提升和区间，而非只显示单一百分比。
- 同一标的结论演化、实际表现和记忆实验标记。

系统状态增加完整性审计积压、预测编译积压、v3 验证积压和实验队列，不与 Gateway 模型状态混为一谈。

## 发布顺序

1. 点时保护、完整性数据模型、旧数据重审、默认排除和安全重评估。
2. forecast.v1、validation.v3、基线统计及详情页。
3. 历史辅助 A/B、组合回放和聚合分析页。

每阶段独立迁移、部署和回滚。后一阶段只依赖前一阶段已经发布的数据合同，不通过临时字段耦合。

## 总体成功标准

- `git diff -- TradingAgents` 始终为空，子模块指针不变。
- 所有历史数据使用公开可用日而非会计期末日过滤；无法证明时失败关闭。
- 旧报告和验证可原样读取，默认统计明确排除风险记录。
- 新预测具备可机器验证的期限、口径、置信度和中性原因。
- 新验证从下一可交易时点开始，并在同一数据口径下与简单基线比较。
- 历史辅助是否有效由配对实验回答，而不是按不同日期的观察性样本推断。
- 组合收益包含成本、仓位约束和不可执行状态，不把方向正确率冒充投资收益。
- REST、MCP、Web 均可读取完整审计链，且不会泄露 API 密钥或未脱敏原始数据。
