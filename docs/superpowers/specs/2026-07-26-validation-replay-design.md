# 评估结果验证回放设计

## 目标

在评估详情页中，为 1、5、20 个交易日的结果验证提供可复核的图形化回放。页面必须同时回答：原始判断是什么、验证窗口内价格如何变化、系统为何给出当前验证结论。

本功能只修改 MarketQuorum 平台层，不修改 TradingAgents。

## 审计原则

1. 数据库中已经保存的收益率、基准收益、Alpha、MAE 和 MFE 是结果事实，浏览器不得重新计算或覆盖。
2. K 线和基准曲线只能读取该次验证绑定的不可变价格产物，不得使用页面打开时临时获取的实时行情。
3. 页面必须显示价格来源、采集时间、产物 ID、SHA-256 和计算规则版本。
4. TradingView 等外部网站仅用于延伸研究，必须明确标注其数据可能因复权或历史修订而与封存产物不同。
5. 20 个交易日验证指入场交易日收盘到其后的第 20 个交易日收盘，包含入场节点时图上共有 21 个验证价格节点。

## 信息架构

评估详情页的“表现验证”区域独占一行，并按以下顺序展示：

1. 结果摘要：原始评级、方向是否正确、标的收益、基准收益、Alpha。
2. 验证期限切换：1 日、5 日、20 日；默认选择已完成的最长周期。
3. 标的复权日 K 线：展示评估日前的背景区间、验证起点、1/5/20 日出口、目标价、MAE 和 MFE。
4. 相对表现图：标的与基准在验证起点归一化为 100，使用同一时间轴展示。
5. 计算与数据依据：默认折叠，包含精确日期、价格、公式口径、来源、采集时间、产物 ID、哈希和规则版本。
6. 外部研究入口：按交易所和标的打开 TradingView 日线图，并支持复制本次验证区间。

验证尚未到期、行情暂不可用、验证失败、用户缺少产物读取权限时，区域显示明确状态，不尝试绘图。

## API 契约

现有 `GET /api/v1/assessments/{run_id}/validations` 扩展以下字段：

- `trigger_results`：评级、方向、方向正确性、目标价命中、入场/退出价格和日期。
- `data_artifact_id`：精确绑定的价格产物。
- `error_code`：验证未完成时的机器可读原因。
- `calculation_version`：当前固定为 `validation.v1`。

价格数据仍通过现有 `GET /api/v1/artifacts/{artifact_id}` 获取，并继续执行文件路径和 SHA-256 完整性校验。验证价格产物改为永久保留；它只包含公开市场价格，不含用户敏感信息。

## 图表数据口径

价格产物中的原始 OHLC 与复权收盘同时保留。审计图默认使用与验证计算一致的复权口径：

```text
adjustment = adjusted_close / close
adjusted_open = open × adjustment
adjusted_high = high × adjustment
adjusted_low = low × adjustment
```

相对表现曲线以验证入场日为 100：

```text
normalized = adjusted_close / entry_adjusted_close × 100
```

图表转换只负责显示，不重新产生数据库验证指标。若原始评估日不是交易日，页面分别标出“评估日”和下一个可交易的“验证起点”。

## 外部链接

TradingView 链接携带规范化交易所和标的。任意历史起止日期没有稳定的公开深链契约，因此页面同时展示并允许复制精确日期范围，不承诺第三方打开后自动定位日期。

外部入口旁固定显示：

> 外部行情仅供延伸研究，可能因复权方式或数据修订而与本次封存验证略有差异。

## 技术方案

前端使用 `lightweight-charts` 绘制蜡烛图和归一化折线图，保留 TradingView 归属标识。价格转换、状态选择、外部链接生成拆分为纯函数并单独测试；React 组件测试关注真实文字、状态、期限切换和审计信息，不断言 Canvas 像素。

后端通过 Pydantic 明确建模验证触发结果，避免前端依赖无约束 JSON。原有 MCP 验证资源会自然获得新增字段，保持 REST 和 MCP 的结果一致性。

## 验收标准

- 已完成的 20 日验证默认展示完整的回放摘要和图表。
- 1、5、20 日期切换不会混用产物或指标。
- 页面数值与 API 已保存指标完全一致。
- 图表使用对应产物并展示产物 ID、SHA-256、来源和采集时间。
- 未完成、失败、无权限和产物损坏均有可理解的降级状态。
- TradingView 链接携带正确交易所和标的，复制内容包含精确验证日期范围。
- 前后端测试、类型检查、Lint 和生产构建全部通过。
