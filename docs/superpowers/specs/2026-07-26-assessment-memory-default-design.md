# 新建评估记忆默认策略与页面优化设计

## 目标

优化新建评估页面对“评估记忆”的表达和默认行为，让日常 Web 派发优先利用同标的已验证经验，同时保留可复现的独立评估入口，并避免用户把历史辅助误解为模型训练或“引用越多越可靠”。

本次只修改 TradingNG 外部 Web 表单及其展示样式，不修改 `TradingAgents/`、平台 API 契约、MCP 契约或历史记忆选择算法。

## 已确认决策

1. Web 新建评估默认选择 `historical`。
2. REST 和 MCP 在调用方省略 `memory_mode` 时继续默认 `independent`，保持现有外部程序行为兼容。
3. 历史辅助最多引用 5 次同标的旧评估，不向用户开放数量输入框。
4. 独立评估始终可显式选择，用于基准对照、争议复核和避免历史观点锚定。
5. 页面明确说明历史辅助是可审计的上下文注入，不训练或修改模型权重，也不保证预测持续改善。

## 历史辅助的准确含义

平台现有外部层在任务准入时构建不可变记忆快照。只有满足以下全部条件的记录才能进入快照：

- 与本次评估是同一标准化标的；
- 旧任务成功并形成结构化投资结论；
- 至少一个表现验证已完成且具备收益、Alpha、最大有利/不利波动等必要字段；
- 旧评估的分析日期严格早于本次分析日期；
- 表现验证的退出交易日严格早于本次分析日期，防止未来数据泄漏；
- 同一次旧评估最多贡献一个记忆条目，现有排序优先选择更成熟周期；
- 最终最多选择 5 次旧评估。

没有合格记录时，任务仍以 `historical` 模式入队，但记忆快照包含 0 个来源，TradingAgents 收到空的历史上下文，运行效果等同独立评估。页面不得把这种情况展示成错误。

历史上下文只进入 Portfolio Manager 的最终组合判断，不进入市场、新闻、社交情绪、基本面分析师或研究辩论阶段。历史评级是校准样本而不是投票，当前日期证据始终优先。

## 为什么保持最多 5 条

原始 TradingAgents 的 `TradingMemoryLog.get_past_context` 默认选择同标的最近 5 条完整经验，并可附加 3 条跨标的反思。本平台目前更保守，只构建同标的经验，不使用跨标的迁移。

5 条是上下文多样性和锚定风险之间的上限，不是目标数量：

- 1–3 条成熟、差异明显的记录通常已经能校准评级语义和风险控制；
- 更多同源记录会重复相似市场状态和提示词偏差，稀释当前证据；
- 历史表现存在状态漂移，正确的旧结论也可能不适用于当前市场；
- 当前内部样本没有呈现“来源数量越多，方向准确率越高”的单调关系。

因此页面只陈述“最多 5 条”，不提供追求更大数量的控制项。未来若升级选择算法，应优先提高来源质量、差异性和市场状态相关性，而不是提高数量上限。

## 页面信息架构

### 评估记忆选择器

把现有原生下拉框改为一个可访问的 `fieldset`，包含两个整块可点击的单选卡片：

1. **历史辅助**
   - 带“推荐”标记并默认选中；
   - 主说明：参考同标的、分析日前已经完成表现验证的旧评估；
   - 辅助说明：最多 5 条，无合格记录时以零记忆继续运行；
   - 风险说明：当前证据优先，历史结论不是投票。
2. **独立评估**
   - 主说明：不读取任何旧评估结论；
   - 辅助说明：适合基准对照、争议复核或需要完全隔离历史观点的任务。

卡片使用原生 radio 控件保持键盘、屏幕阅读器和表单语义。选中态通过边框、浅色背景和单选状态共同表达，不能只依赖颜色。

### 机制说明

选择器下方使用一条紧凑说明而不是默认展开的大段文字：

> 历史辅助不会训练或修改模型，只向最终投资判断提供可审计的历史校准信息。

说明中的“可审计”链接不新增路由；实际引用来源继续在任务完成后的评估详情中查看。页面不尝试在提交前预测可用来源数量，因为当前 API 没有预览契约，且任务真正准入前数据库状态仍可能变化。

### 表单布局

分析日期、分析深度和输出语言继续保留在紧凑配置网格中。评估记忆选择器横跨整个表单宽度，避免长说明被四列网格压成窄段落。桌面端两张卡片并排，窄屏单列堆叠。

## 数据流与兼容性

1. 页面初始状态把 `memoryMode` 设为 `historical`。
2. 用户切换任一选项时继续刷新幂等键。
3. 提交负载仍发送既有 `memory_mode` 字段，不增加字段。
4. 后端、REST OpenAPI、MCP 工具和调度器默认值不变。
5. 重试继续沿用原请求的已请求配置和准入时固定的记忆快照规则。
6. 历史记忆来源数量和哈希继续通过运行详情审计，不在表单中缓存或推测。

## 持续进化边界

当前能力应描述为“带结果反馈的持续经验积累”，不能描述为模型持续训练或保证越来越聪明。系统会让后续 Portfolio Manager 读取已经验证的经验，但不会修改 Codex 或其他模型的参数。

以下增强属于后续独立设计，不包含在本次实现中：

- 按时间衰减、市场状态、验证质量和信息差异性对候选记忆评分；
- 在最近经验、重大错误、重大成功和相似市场状态之间分配来源配额；
- 自动维护历史辅助与独立评估的影子对照；
- 检测长期表现退化并自动降权、隔离或回滚记忆策略；
- 在可信行业分类和市场状态匹配后评估跨标的反思迁移。

## 错误与边界处理

- 0 条可用历史不是错误，不阻止派发；
- 用户选择独立评估时必须明确提交 `independent`；
- 批量标的共享所选模式，但每个标的在准入时独立构建自己的记忆快照；
- 历史日期评估继续执行严格的退出交易日边界，不因 Web 默认改变而放宽；
- 表单服务端错误和容量提示沿用现有处理，不与记忆说明混合。

## 测试与验收

- 初始页面把“历史辅助”单选卡片标记为选中和推荐；
- 默认提交负载包含 `memory_mode: "historical"`；
- 切换“独立评估”后负载包含 `memory_mode: "independent"`；
- 页面包含“最多 5 条”“零记忆继续”“不会训练或修改模型”和“当前证据优先”等准确说明；
- 不再出现旧的“独立评估（默认）”下拉选项；
- radio 卡片支持可访问名称、点击标签和键盘选择；
- 桌面和窄屏均不产生异常换行或横向溢出；
- 前端测试、Lint、类型检查和生产构建通过；
- 全平台回归通过，且 `TradingAgents/`、REST 和 MCP 契约无修改。
