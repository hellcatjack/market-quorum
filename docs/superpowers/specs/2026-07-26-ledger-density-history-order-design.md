# 标的台账密度与历史排序优化设计

## 目标

在不减少关键研究信息、不修改 TradingAgents 和后端业务契约的前提下，提高标的研究台账的横向信息密度，并让标的下钻页优先回答“最新判断是什么”，同时修复日期、状态、指标和元数据的异常换行。

## 方案选择

采用四列语义台账，不继续压缩现有六列，也不改成大卡片网格：

1. **标的**：中文名称、ticker、交易所和资产类型。
2. **结论与表现**：最新有效评级、分析日期，以及预测方向、验证周期、收益、Alpha、方向与目标价结果。
3. **可靠性与变化**：同周期样本可靠性和相对上次成功评级的变化。
4. **运行**：最新任务状态及成功、运行、排队、异常和总事件数。

总览不再展示完整 executive summary。完整结论继续在评估详情和标的历史中查看。这样由结构化指标而不是最长摘要决定行高。

预测—表现不再作为一个允许浏览器任意断行的长字符串渲染。评级、箭头、周期、收益、Alpha、方向和目标价分别成为不可拆分的短语义单元，由容器在单元之间换行。

## 标的历史排序

默认使用“最新在前”。从总览进入标的页属于当前判断下钻，最新结论、最近异常和刚成熟的验证应出现在首屏。

页面提供“最新在前 / 最早在前”双向切换：

- 最新在前是默认阅读方式；
- 最早在前用于按因果顺序复盘；
- 评级变化始终先按时间正序计算，再按选择的展示顺序排列，不能因倒序展示反转变化含义；
- 重试仍归入对应研究事件并默认折叠。

标题和时间线方向说明必须与当前排序一致，避免用户把倒序时间线理解为自然时间正序。

## 换行与响应式规则

- 日期、评级、状态、周期、收益和 Alpha 使用 `white-space: nowrap`，只在语义单元之间换行；
- 台账宽屏使用稳定的四列比例，主信息列获得剩余空间，其余列设置合理的最小宽度；
- 运行计数使用紧凑的单行/双行统计，不用多个宽度不一致的大胶囊；
- 历史事件头部采用日期、创建时间和状态的显式网格，桌面端不互相挤压；
- 投资摘要允许自然中文段落换行，但禁止按钮和元数据把正文压成窄列；
- 配置哈希是唯一允许在必要时安全截断/断行的长字符串；
- 820px 以下继续退化为分组卡片，480px 以下才改成单列。

## 组件边界

- `InstrumentLedgerTable.tsx` 负责四列结构和结构化预测结果，不改变 API。
- `instrumentPresentation.ts` 新增预测结果分段投影，保留已有文本格式函数供兼容测试使用。
- `instrumentHistory.ts` 负责按 request 归组、时间排序和稳定的评级变化投影。
- `InstrumentHistoryPage.tsx` 只维护排序状态并渲染投影结果。
- `global.css` 负责列比例、语义换行和响应式规则。

## 测试与验收

- 台账只出现四个表头；成熟验证的评级、收益、Alpha、方向仍完整可读；
- 长摘要不再进入台账行，不会抬高整行；
- 长评级和指标不会在词语内部断行；
- 标的历史默认第一项是最新事件；
- 切换“最早在前”后第一项变为最早事件；
- 两种顺序下评级变化文字保持相同业务含义；
- 历史页日期、状态、详情按钮、验证矩阵和元数据在桌面与窄屏均无异常挤压；
- 前端全量测试、Lint、类型检查、生产构建和部署健康检查通过；
- `TradingAgents/` 无修改。
